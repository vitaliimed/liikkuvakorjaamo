# GA4, Google Ads и рекламные события

## Что уже в коде

GA4: **G-MXX9XCNCRB**. Прямая установка Google tag; отдельный GTM-контейнер не требуется. Не добавляйте второй такой же Google tag через GTM: иначе события могут дублироваться.

GA4 и рекламные ID управляются в админке → Основные настройки → Аналитика, реклама и согласие. Для Google Ads нужны ваш **AW-ID** и **Conversion label**. Для Meta нужен Pixel ID. Неизвестные идентификаторы оставлены пустыми — чужие или вымышленные ID не используются.

Стандартная схема согласия — basic: Google/Meta/LinkedIn/TikTok не загружаются до соответствующего разрешения. Четыре параметра Consent Mode v2: `analytics_storage`, `ad_storage`, `ad_user_data`, `ad_personalization`. Разрешение рекламы и аналитики можно выбирать отдельно. Вариант «только реклама» также загружает Google Ads корректно.

`generate_lead` вызывается **после сохранения заявки сервером**, только при наличии выданного сервером случайного `submission_id`. Ошибка формы, недоступная база и honeypot не считаются конверсией. Повторный вызов с тем же ID в браузере подавляется. Страница благодарности не создаёт новую заявку и повторно её не считает.

Сохранённая заявка и доставка уведомлений — разные этапы. Даже если Telegram временно недоступен, сохранённая заявка считается полученной. Cloud Tasks повторяет неудачную обработку. Если не удалось поставить задачу в очередь, заявка остаётся в админке со статусом ошибки и кнопкой повторной обработки. Синхронная отправка всех уведомлений не задерживает форму на минуту.

## События

| Событие | Когда | Назначение |
|---|---|---|
| `page_view` | Просмотр при согласии на GA4 | Посещения |
| `generate_lead` | Сервер подтвердил сохранение | Основная заявка |
| `lead_form_start` | Первое действие в форме при согласии | Начало заполнения |
| `lead_submit_attempt` | Отправка прошла до обработчика формы | Попытка |
| `lead_validation_error` | Нативная проверка обязательного поля | Ошибка поля, без его значения |
| `lead_submit_success` | Успешный ответ API | Технический контроль; не вторая основная конверсия |
| `lead_submit_error` | Ответ API с ошибкой | Отказы формы |
| `lead_submit_network_error` | Сетевая ошибка | Доступность |
| `lead_photo_upload` | Добавлены фотографии | Использование формы |
| `lead_use_location_click` | Нажат запрос геолокации | Использование функции |
| `lead_map_open` | Открыта карта | Использование функции |
| `lead_map_point_confirmed` | Выбрана точка | Координаты в аналитику не передаются |
| `phone_click` | Нажата телефонная ссылка на главной | Намерение позвонить; не подтверждённый разговор |
| `email_click` / `whatsapp_click` | Нажаты соответствующие ссылки | Микроконверсии, если ссылка добавлена |
| `mobile_sticky_form_click` | Мобильная кнопка заявки | Мобильная навигация |
| `language_switch` | Выбран FI/EN | Языки |
| `navigation_click` | Переход в меню | Навигация |
| `view_pricing` | Блок цен виден посетителю | Интерес к стоимости |
| `scroll_depth` | 25/50/75/90% страницы | Глубина просмотра |

Имена, телефоны, email, номера автомобиля, адреса, тексты заявок и фотографии не отправляются в GA4-события. `page_location` очищается от произвольных query-параметров; для рекламной атрибуции после разрешения рекламы сохраняются только допустимые `gclid`, `gbraid`, `wbraid`. UTM должны содержать названия кампаний, а не персональные данные. GA4 Enhanced Measurement нужно проверить отдельно: код сайта не управляет всеми настройками вашего потока в интерфейсе Google.

В `generate_lead` не передаётся выезд 70 € как выручка: заявка ещё не означает оплату. Стоимость лида можно задать в настройках конверсии после оценки доли закрытия и среднего дохода. Поступления фиксируются в новой таблице дохода; автоматического импорта оплаченных работ в Ads, Meta CAPI или серверного GA4 Measurement Protocol этот релиз не делает.

## Настройка GA4

1. Admin → Data streams: проверьте поток с `G-MXX9XCNCRB`, его назначение и настройки. Этот ID уже используется по вашему указанию.
2. Часовой пояс свойства: **Europe/Helsinki**, валюта — EUR, если это соответствует вашему общему свойству.
3. Откройте новый сайт, разрешите аналитику и проверьте `page_view` в Realtime/Tag Assistant.
4. Отправьте одну собственную тестовую заявку. Проверьте один `generate_lead`.
5. Admin → Events/Key events: отметьте `generate_lead` как ключевое событие. Не делайте `lead_submit_success` вторым основным событием заявки.
6. Для сравнения доменов используйте встроенное измерение **Host name**. При необходимости зарегистрируйте `site_domain` и `site_brand` как пользовательские измерения уровня события. Не регистрируйте уникальный `event_id` как отчётное измерение: это высокая кардинальность.
7. Проверяйте Enhanced Measurement: автоматические form_start/form_submit могут существовать параллельно с нашими событиями. Не используйте их как подтверждение сохранённой заявки.
8. Настройте фильтр внутреннего трафика сначала в Testing; тестовые визиты не должны неожиданно исчезать из проверки.

Если в том же GA4 находятся AutoHelp и новый сайт, стандартный импорт общего `generate_lead` в Ads может охватывать оба домена. Для раздельного учёта создайте в GA4 отдельное событие, например `liikkuva_generate_lead`, по условиям `event_name = generate_lead` и `site_domain = liikkuvakorjaamo.fi`; затем отметьте и импортируйте именно его. Не назначайте оба события основными для одной кампании.

## Google Ads — рекомендуемая настройка

**Вариант A: прямая конверсия Google Ads.**

1. Создайте действие-конверсию сайта «Liikkuva — заявка» категории Lead/Submit lead form.
2. Count: **One**. Основная цель кампании — эта заявка.
3. Скопируйте AW-ID и label в админку. Сохраните.
4. Включите auto-tagging Google Ads.
5. Конверсия передаёт `transaction_id`, равный ID сохранённой заявки. Отправка зависит от согласия на рекламу.
6. Импорт GA4 можно использовать как Secondary для сравнения, но не как вторую основную конверсию этой же заявки.

**Вариант B: только импорт GA4.**

Свяжите GA4 с Google Ads и импортируйте `liikkuva_generate_lead` (при раздельном учёте доменов) либо корректно отфильтрованный `generate_lead`. Не заполняйте direct Ads conversion label, если прямой маршрут не нужен. Наличие Ads tag без label может использоваться отдельно для аудиторий при соответствующем согласии.

Для звонков `phone_click` — дополнительная цель. Подтверждённые звонки и длительность разговора требуют call reporting/подменного номера либо отдельного call tracking. Нажатие ссылки не доказывает состоявшийся разговор.

Не заявляйте работу «24/7», «за 15 минут», «все марки без исключений» или цену ремонта, если это не соответствует фактическому обслуживанию.

## Meta, LinkedIn, TikTok

- Meta: PageView после маркетингового согласия; Lead после сохранения, с eventID. Pixel ID задаётся в админке.
- LinkedIn: Partner ID + event-specific conversion ID. Конверсия заявки — после сохранения при согласии.
- TikTok: Pixel ID; SubmitForm после сохранения при согласии.
- Не устанавливайте параллельно те же пиксели через другой шаблон/GTM. Server-side CAPI в этот релиз не входит.

## Проверка перед расходованием бюджета

| Сценарий | Ожидаемое поведение |
|---|---|
| Отказ от всех необязательных cookies | Форма работает, GA4/рекламные теги не загружаются |
| Только аналитика | GA4 работает; рекламные конверсии не отправляются |
| Только реклама | Рекламные теги работают; GA4 не отправляет события |
| Все разрешены | События в соответствующие системы |
| Email без телефона | Форма отклонена, заявки/конверсии нет |
| Успешная заявка | Запись в админке и один generate_lead при согласии |
| Обновление thank-you | Нет повторной конверсии заявки |
| Ошибка API | Событие ошибки; нет generate_lead |
| Смена домена в отчёте | Host name отличает AutoHelp и Liikkuva |

Проверьте Tag Assistant, GA4 Realtime/DebugView и diagnostics нужной рекламной системы. Получение данных рекламными аккаунтами нельзя подтвердить только локальным тестом кода. Блокировщики и отказ от cookies закономерно уменьшают измеряемое число заявок: сверяйте с админкой.
