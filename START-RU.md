# Liikkuva Auto Korjaamo — полный комплект запуска

Версия: 25 октября 2026. Домен: **liikkuvakorjaamo.fi**. Это самостоятельный Go-проект в `source/`, а не только макет. Публикацию выполняете вы из Cloud Shell. Git не требуется.

## Что входит

- Третий скандинавский дизайн: светлый фон, синий акцент, крупная типографика, мобильное меню и закреплённая кнопка заявки.
- Финский и английский языки. Выезд **70 €**, диагностика **от 50 € отдельно**. Если требуются оба действия — от 120 €. Запчасти и дополнительные работы согласуются отдельно.
- Форма: телефон обязателен, email необязателен; фотографии, адрес, карта и геолокация по действию посетителя.
- Русская админка `/admin`: контент, цены, цвет, размер шрифта, изображения, SEO, аналитика, заявки, статусы, письма и модерация отзывов. Отдельная форма письма `/admin/email`, включая вложения.
- GA4 **G-MXX9XCNCRB**, Consent Mode v2, события заявки и полезных действий. Google Ads/Meta/LinkedIn/TikTok активируются после заполнения ваших ID и согласия посетителя.
- Заявки в тот же Telegram-чат, с меткой нового домена. Отдельные Firestore, хранилище фото, очередь, настройки, секреты и **новая Google-таблица**.
- Полный исходный код, Dockerfile, установка, обновление, подключение домена, настройка почты и проверки.

Фото первого экрана — иллюстрация услуги, не фотография реального сотрудника. Для доверия и рекламы позже замените её собственной качественной фотографией через админку. Примеры ситуаций не выдаются за отзывы клиентов.

## 1. Подготовьте новую таблицу

1. Откройте https://script.google.com/home и создайте **новый проект**.
2. Вставьте содержимое `apps-script/Code.gs` в `Code.gs`. Не заменяйте скрипт таблицы AutoHelp.
3. Выполните `setupNewLiikkuva`. Подтвердите доступ в своём аккаунте.
4. Откройте ссылку на созданную таблицу из журнала. Создаются месяцы, годовой доход, статусы; текущий месяц перемещается первым при поступлении заявки.
5. Project settings → Script properties: скопируйте `WEBHOOK_TOKEN`. Не публикуйте его и не отправляйте в чат.
6. Deploy → New deployment → Web app. Execute as: **Me**. Who has access: **Anyone**. Запись защищена секретным токеном; таблица не становится общедоступной.
7. Сохраните URL вида `https://script.google.com/macros/s/.../exec`.

Установщик проверяет связь без создания заявки. В таблице можно указывать доход и статус «Успешный» — только такие строки учитываются в итогах дохода. Статусы таблицы и админки редактируются независимо: автоматической двусторонней синхронизации нет.

## 2. Загрузите архив в Cloud Shell

Откройте https://shell.cloud.google.com под аккаунтом, который управляет AutoHelp. Загрузите `Liikkuva_Autokorjaamo_Ready.zip` через Upload file. Затем:

```bash
cd "$HOME"
unzip Liikkuva_Autokorjaamo_Ready.zip
cd Liikkuva_Autokorjaamo_Ready
python3 install.py
```

При запросе вставьте URL **нового** Apps Script и его токен. Ввод токена скрыт.

По умолчанию:

| Параметр | Значение |
|---|---|
| Google Cloud project | `seventh-chassis-247718` |
| Регион | `europe-north1` |
| Новый Cloud Run | `liikkuva-landing` |
| Исходный сервис для Telegram/SMTP | `autohelp-landing` |
| Новый исходный код | `~/lending/LiikkuvaKorjaamo` |
| Firestore database | `liikkuvakorjaamo` |
| Коллекции | `liikkuva_leads`, `liikkuva_reviews`, `liikkuva_settings` |
| Bucket | `seventh-chassis-247718-liikkuva-files` |
| Очередь | `liikkuva-lead-processing` |
| Service account | `liikkuva-runtime` |

Установщик сначала проверяет Go-код. Затем создаёт отдельные ресурсы, переносит разрешённые настройки Telegram/SMTP, копирует реальные контактные данные и реквизиты из настроек AutoHelp, задаёт новый SEO и создаёт новый пароль админки. Старые заявки, отзывы и тексты не копируются. Сервис AutoHelp не обновляется.

Нужны права на создание ресурсов и включённая оплата Google Cloud. Cloud Run, Firestore, Storage, Cloud Tasks, Secret Manager и Cloud Build не являются безусловно бесплатным хостингом. На новом сервисе установлены min-instances=0, max-instances=5.

После успеха появятся адрес `.run.app`, адрес админки и команда получения пароля. Откройте админку и проверьте телефон, юридическое название, Y-tunnus и рабочие часы. Для цены и цвета есть настройки вверху основного раздела.

Если установка остановилась после создания сервиса, не запускайте её снова вслепую: прочитайте ошибку. Первичная установка блокирует перезапись уже существующего сервиса. Для работающего сайта используется `update.py`. Секреты и пароли из ошибок не публикуйте.

## 3. Подключите домен с HTTPS

Рекомендуемый комплектом вариант — **Firebase Hosting → Cloud Run**. Это отдельный Hosting site в том же Google Cloud проекте. Firebase поддерживает Cloud Run в `europe-north1`; cookie админки уже совместима с Hosting.

1. Откройте https://console.firebase.google.com/ и добавьте Firebase к **существующему** проекту `seventh-chassis-247718`. Не создавайте другой Google Cloud проект.
2. Выполните из папки комплекта:

```bash
python3 hosting.py
```

3. Пройдите вход Firebase CLI в своём браузере. Скрипт создаст отдельный Hosting site `liikkuva-seventh-chassis-2477` и опубликует только его конфигурацию.
4. Firebase Console → Hosting → этот site → Add custom domain → **liikkuvakorjaamo.fi**.
5. В DNS добавьте **именно записи, которые выдаст Firebase**. Не угадывайте IP и не удаляйте почтовые MX/TXT.
6. `www.liikkuvakorjaamo.fi` добавьте в Hosting как перенаправление на основной домен.
7. Дождитесь статуса Connected и HTTPS. Если DNS управляется Cloudflare, записи сайта на время подключения оставьте DNS only.
8. Откройте `https://liikkuvakorjaamo.fi/admin`, войдите, сохраните небольшое изменение и проверьте повторное открытие страницы.

Скрипт работает с отдельной конфигурацией в `firebase-hosting/`. `firebase init` не нужен. Если site уже создан, но локальный marker потерян, не удаляйте действующий Hosting site: проверьте его ID в Firebase Console и восстановите файл `firebase-hosting/site-created.json` с фактическими `project` и `site`.

Старый вариант `python3 install.py domain` сохранён как дополнительный путь Cloud Run domain mapping. Google помечает его как Preview и не рекомендует для production; для планируемой рекламы используйте описанный выше Hosting. Тарифы/квоты Firebase и Google Cloud проверяются в вашем аккаунте.

## 4. Настройте свою почту

Полная инструкция — `EMAIL-RU.md`. Пока новый домен не подтверждён в Brevo, установщик сохраняет действующий подтверждённый отправитель AutoHelp. Отображаемое имя письма — Liikkuva Auto Korjaamo.

После настройки DNS и отправителя:

```bash
python3 configure_email.py
```

Скрипт меняет настройки только нового Cloud Run. SMTP key вводится скрыто и сохраняется в Secret Manager. После этого в админке укажите новый адрес для контактов и проверьте свою тестовую заявку.

## 5. Проверьте сайт перед рекламой

1. FI/EN: телефон, почта, реквизиты, часы, цены, условия и ссылки.
2. Своя заявка: появляется в админке, Telegram и **новой** таблице. Телефон без email принимается; email без телефона отклоняется.
3. Фотография открывается из заявки. Не отправляйте фото клиентов для теста.
4. На вашу почту приходит подтверждение. Из админки отправляется ответ с PDF/фото.
5. Аналитика после согласия: `page_view`, начало формы, **один** `generate_lead` после успеха. Без согласия на аналитику GA4-события не отправляются.
6. Google Ads: выберите **один основной способ** учёта заявки — прямой Ads tag или импорт GA4. Подробности в `ADS-ANALYTICS-RU.md`.
7. Search Console: DNS-подтверждение домена и sitemap. Подробности в `SEO-ANALYTICS-RU.md`.

Код проверен локально. Реальная доставка в ваш Telegram, SMTP, Apps Script, обработка Cloud Tasks, выпуск сертификата и получение данных в рекламных аккаунтах проверяются после установки. В этом комплекте нет ваших секретов; эти интеграции отсюда не запускались.

Проверка без создания заявок и отправки писем:

```bash
python3 check_live.py
```

Она проверяет страницы и показывает ревизию с текущим трафиком. Для первичной проверки до подключения домена можно передать `--url https://ваш-адрес.run.app` из вывода установщика.

## 6. Последующие обновления — без Git

Редактируйте **одну выбранную рабочую папку** `~/lending/LiikkuvaKorjaamo`, а не одновременно её и `source/` в архиве. После ваших изменений:

```bash
cd "$HOME/Liikkuva_Autokorjaamo_Ready"
python3 update.py --source "$HOME/lending/LiikkuvaKorjaamo"
```

Скрипт проверит код, соберёт образ, создаст ревизию без пользовательского трафика, проверит `/healthz` и главную, затем направит **100% трафика на эту конкретную ревизию**. Данные, настройки CMS и секреты сохраняются. Он не делает Git-операций и не создаёт локальных резервных копий. Предыдущие Cloud Run revisions остаются доступны для отката через Manage traffic.

Если загружаете целиком новый комплект исходников, используйте `python3 update.py --source ./source`. Это заменит программный код новым релизом, поэтому сначала перенесите свои изменения файлов. CMS-настройки и заявки находятся в Firestore и не зависят от этой папки.

## Какие файлы менять вручную

| Задача | Файл в рабочем исходном проекте |
|---|---|
| Основные тексты по умолчанию FI/EN | `liikkuva-content.json` |
| Разметка главной | `landing.html` и `templates/landing.html` — одинаково |
| Публичные стили | `static/css/pro.css`, `static/css/style.css` |
| Русская админка | `admin.html`, `templates/admin.html`, `static/css/admin-mobile.css` |
| Стандартные SEO-страницы | `static/seo/*.html` |
| События | `static/js/events.js`, `app.js`, `consent.js` |
| Метаданные по умолчанию | `seo-defaults.json` |
| Карта сайта | `static/sitemap.xml` |

Для повседневных изменений используйте админку: её значения имеют приоритет над стандартными текстами. Ценовые маркеры `{visit}`, `{diagnostic}`, `{total}` позволяют подставлять текущие значения без ручного исправления сумм.
