# Почта, общий Telegram-бот, логотип и ночная тема

Проект: `liikkuva-korjaamo`. Сервис определяется по действующему Firebase Hosting.
Текущий сервис: `liikkuva-preview`, регион `europe-north1`.

## 1. Что приготовить

| Данные | Где взять | Куда вводить |
|---|---|---|
| SMTP login | Brevo → Settings → SMTP & API → SMTP → Login | Запрос `SMTP login` в Cloud Shell |
| SMTP key | Там же, Generate a new SMTP key | Скрытый запрос `SMTP key / password` |
| Отправитель | Подтверждённый Sender в Brevo | `service@liikkuvakorjaamo.fi` |
| Telegram bot token | Текущая настройка `TELEGRAM_BOT_TOKEN` работающего AutoHelp или владелец бота в BotFather | Скрытый запрос `Telegram bot token` |
| Telegram Chat ID | Текущая настройка `TELEGRAM_CHAT_ID` AutoHelp | Запрос `Telegram Chat ID` |

Для общего бота используйте существующий токен и тот же чат. Не отзывайте токен
в BotFather: AutoHelp использует его тоже. Если в Cloud Run указан Secret Manager,
значение находится в соответствующей версии секрета. В чат с помощником ключи
передавать не требуется.

## 2. Входящая почта

В Cloudflare откройте Email Routing для `liikkuvakorjaamo.fi`.
В актуальном меню раздел также доступен через Compute → Email Service → Email Routing.

1. Destination Addresses: добавьте `medynikv@gmail.com`, откройте письмо подтверждения.
2. Routing rules: правило для `service@liikkuvakorjaamo.fi`, действие Forward to Email,
   назначение — подтверждённый Gmail, состояние — Enabled.
3. Проверьте DNS-записи, которые показывает сам Cloudflare для этого домена.
4. Отправьте на сервисный адрес своё письмо с другого ящика и проверьте получение.

Входящая пересылка и SMTP-отправка приложения настраиваются отдельно.

## 3. Исходящая почта и Telegram

В Brevo подтвердите домен `liikkuvakorjaamo.fi` и Sender
`Liikkuva Auto Korjaamo <service@liikkuvakorjaamo.fi>`.
Если домен уже подтверждён, повторное добавление записей не требуется.
Используйте SMTP key; пароль аккаунта и API key для этого поля не подходят.

```bash
(
set -e
git -C "$HOME/liikkuva-release" pull --ff-only origin main
python3 "$HOME/liikkuva-release/update.py" --configure-email --configure-telegram
python3 "$HOME/liikkuva-release/update.py" --check-integrations
)
```

SMTP host: `smtp-relay.brevo.com`, port: `587`.
Параметры вводятся по очереди; секреты скрыты и передаются в Secret Manager
через stdin. Обновляется только сервис Liikkuva. Перед сохранением Telegram
проверяются `getMe` и `getChat`. Проверка не отправляет сообщений и не меняет
webhook, команды или поток входящих обновлений общего бота.

Для настройки только одного сервиса оставьте соответствующий параметр:
`--configure-email` или `--configure-telegram`.

`--check-integrations` читает наличие настроек, не меняет облачные ресурсы
и не подтверждает доставку. В админке краткое состояние находится в
«Помощь и термины». Адрес на сайте задаётся отдельно:
«Основные настройки → Почта для связи». Адрес восстановления:
«Доступ и почта».

## 4. Как выглядит заявка в общем боте

Пример для финской формы при цене выезда 70 €:

```text
🟦 LIIKKUVA · liikkuvakorjaamo.fi
#Liikkuva

🚗 Uusi liidi

Aika: время по Хельсинки
Nimi: Тест Liikkuva
Puhelin: номер из формы
Sähköposti: адрес из формы, если указан
Osoite: адрес автомобиля
Karttalinkki: ссылка на карту, если выбрана точка
Rekisterinumero: TEST-123
Käyntimaksu: 70 €
Kuvia: 1

Viesti:
Описание неисправности от клиента
```

В английской форме названия полей английские. Пустые необязательные поля
не добавляются. Цена берётся из сохранённой заявки, а не из изменившегося позднее
прайса. Каждое вложение дополнительно содержит `#Liikkuva`, домен и регистрационный
номер, чтобы фото двух брендов не смешивались без подписи.

## 5. Логотип и favicon

| Назначение | Поле в админке | Рекомендуемый файл |
|---|---|---|
| Знак рядом с названием Liikkuva | Основные настройки → Логотип путь или URL | SVG или прозрачный PNG 256×256 / 512×512 |
| Основной favicon | Изображения и оформление → Значок сайта SVG | Квадратный SVG, без мелкого текста |
| Растровые favicon | Там же → 32×32 и 16×16 | PNG точно соответствующего размера |
| Дополнительная совместимость | Там же → ICO | Один ICO с размерами 16, 32 и 48 |
| Иконка для iPhone | Там же → Иконка для iPhone | PNG 180×180 |

В шапке уже есть текст названия, поэтому для нынешней компоновки нужен
квадратный знак. Широкий логотип с надписью следует адаптировать под эту компоновку.
В полях задаются общедоступные ссылки или пути; загрузки с компьютера прямо
через эти поля пока нет.

Файлы сайта расположены в `source/static/img/`. Например, загрузите через GitHub
`company-mark.svg`, затем укажите `/static/img/company-mark.svg` в админке.
Изменение файла в репозитории требует обычного обновления сайта. Изменение
общедоступной ссылки в админке применяется после сохранения. При замене файла
под тем же именем добавьте версию к URL, например `?v=2`, чтобы обновить кэш.

## 6. Ночное оформление

«Основные настройки → Цены и оформление → Тема сайта»:

- Светлая — исходный режим.
- Тёмная — тёмный фон, светлый текст и более мягкая яркость фотографии.
- Автоматически по времени Хельсинки — по умолчанию с 21:00 до 07:00.
- Как на устройстве посетителя — настройка светлой/тёмной темы устройства.

Часы можно изменить. Используется `Europe/Helsinki`, включая переходы
на летнее/зимнее время. Одинаковое начало и окончание выключает ночной интервал.
В меню главной есть Auto / Vaalea / Tumma (FI) и Auto / Light / Dark (EN).
На телефоне переключатель находится в раскрывающемся меню. Ручной выбор
сохраняется в браузере; Auto возвращает режим владельца. Изначально сохранённые
сайты продолжают открываться в светлой теме, пока владелец не выберет другой режим.

## 7. До включения приёма заявок

1. Настройте очередь Cloud Tasks, адрес обработчика, служебные ключи и права
   сервисного аккаунта в проекте Liikkuva.
2. Проверьте отдельное хранилище фотографий и именованную Firestore database
   `liikkuvakorjaamo`.
3. Подключите отдельную Google Таблицу и Apps Script: в текущей схеме обработчик
   использует их вместе с Telegram.
4. Просмотрите результат `--check-integrations`. Наличие значений ещё требует
   проверки ресурсов и прав.
5. После готовности инфраструктуры снимите режим настройки командой обновления
   с `--enable-leads`, выполните одну свою тестовую заявку.
6. Проверьте: запись в кабинете, Telegram с правильным тегом, фото, строку таблицы,
   письмо, ответ на сервисную почту и восстановление пароля.
7. В аналитике проверьте выбранные события и согласие посетителя.

До завершения настройки приложения не следует считать наличие бота или SMTP
подтверждением готовности всей цепочки обработки.
