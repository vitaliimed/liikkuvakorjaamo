# Liikkuva CRM — версия доступа и рабочего процесса

Работа выполнена в существующем модуле `source/`, от `feat/crm-core-integration`, базовый коммит `3438a774350871a036b676e1f71ae679edc35b7e`. Старый комплект `liikkuva-crm/` не заменяет интегрированный код. Рабочая ветка — `feat/crm-complete-v2`.

## Реализовано

- Только владелец получает клиентский draft (FI/EN/RU), переписку, снимки событий и настройки. Механик видит назначенные заказы; события выдаются по списку разрешённых полей. Запись клиентских сообщений от механика запрещена сервером. Доступ менеджера пока не включён.
- Технические и собственные внутренние заметки механика. Отдельная техническая история без прежних контактов, переписки, Proposal и финансов отчёта. Владелец получает полные записи. История от последних визитов, раскрываемые подробности.
- Постоянный `vehicle_id`; старое `Vehicle` сохранено для совместимости. Реестр номеров создаётся постепенно. Смена номера сохраняет оба номера для поиска; чужие истории автоматически не объединяются.
- Город, дополнительные зоны, контакты, недельные смены, даты отсутствия, исключения по датам. Зоны проверяются при назначении, рабочие часы — при предложении/подтверждении. Изменение графика не может сделать подтверждённые выезды недоступными. Пересечения остаются защищены транзакцией Firestore.
- Переназначение до начала ремонта освобождает прежнюю бронь и требует нового согласования. Этапы заявки видны в интерфейсе. Заголовок подтверждения исправлен.
- Отчёт: диагностика, работы, детали (или «не меняли»), результат, остаточные проблемы, сумма и способ оплаты. Владелец принимает или возвращает в работу.
- Тарифы отдельно по брендам. Liikkuva: 70 € выезд, 50 € базовая диагностика с пометкой «от» в настройках. AutoHelp: 50 € выезд, работы вводятся отдельно. Снимок прайса сохраняется при создании; согласованное Proposal не пересчитывается. Дополнительные услуги сохраняются в настройках, произвольные строки сметы автоматически не собираются.
- Фото: несколько файлов, предпросмотр, размеры, прогресс, ошибки по имени файла. JPEG/PNG до 20 МБ и 60 Мп, максимум 10 на заказ. Оригинал сохраняется неизменённым, отдельно создаётся JPEG-копия до 1800 px. Оба варианта выдаются через авторизованный API. HEIC/HEIF нужно предварительно экспортировать в JPEG; нормализация EXIF-ориентации отдельно не реализована.
- Ссылка из админки в `/crm/`, отдельная авторизация CRM.

## Переписка и подключения

Заказ является цепочкой: `crm_jobs/{job}/messages`, с job_id и vehicle_id, источником, автором, временем, оригиналом, переводом, вложениями, направлением и статусом. Старые события сохранены. Новые ручные сообщения и письма также попадают в общую коллекцию.

`Server.RecordInboundMessage` — внутренний Go-интерфейс адаптера с идемпотентностью по source/externalID. Вызывающий адаптер обязан проверить подлинность провайдера и связь отправителя с заказом. Публичный WhatsApp webhook не создавался. `Translator`/`TranslateToRussian` — общий контракт перевода FI/EN→RU; провайдер ещё не подключён. Метод TranslateMessage вызывает общий сервис и атомарно сохраняет перевод, проверяя неизменность исходного текста. Доступ к этому действию имеет только владелец. Оригиналы сохраняются отдельно.

Письма отправляет только владелец явно. В Preview отправка заблокирована `CRM_MAIL_SEND_ENABLED=0`. Для ручной отправки после отдельной настройки необходимы CRM_MAIL_SEND_ENABLED=1, CRM_MAIL_FROM (или MAIL_FROM), CRM_MAIL_REPLY_TO при необходимости, SMTP_HOST, SMTP_PORT 465/587, SMTP_USERNAME, SMTP_PASSWORD. Секреты не хранить в Git.

Цепочки сохраняют Message-ID и In-Reply-To/References. Идемпотентный повтор не отправляет второе письмо. Статус accepted означает приём SMTP-сервером, а не доставку. При неопределённом сетевом результате автоматического повтора нет.

Входящие ответы НЕ синхронизируются без подключения провайдера. Подготовлен `/crm/mail/inbound` с Bearer CRM_MAIL_INBOUND_TOKEN от 32 символов; адаптер передаёт message_id, in_reply_to, from, to, subject, body. Неизвестные цепочки и несовпадающий клиент отклоняются и должны оставаться у адаптера для ручного разбора. Реальная отправка/получение почты не проверялись.

## Данные и ограничения

Используется прежняя база `liikkuvakorjaamo`. Массового удаления/перезаписи нет. Существующим механикам нужно заполнить зоны и графики перед новыми назначениями/подтверждениями. Неопределённый город заявки задаётся владельцем в «Контакты и зона».

Исходные фотографии заявок теперь доступны в CRM через авторизованный маршрут intake-photos. Разрешены только сохранённые gs:// ссылки из настроенного GCS_BUCKET_NAME/GCS_PHOTO_PREFIX; механик получает количество фото, но не адреса объектов. Файлы остаются в прежнем хранилище, перенос и изменение оригиналов не выполняются. Полный мобильный прогон и проверка Cloud Storage в настоящем Preview ещё нужны. Раздел «Финансы» читает всю базу и показывает суммы по брендам, механикам и способам оплаты. Разделяет суммы, указанные в отчётах, и суммы принятых/закрытых заказов. Это оперативная сводка, не бухгалтерская отчётность или сверка банковских поступлений. Обзор по-прежнему показывает локальную сводку загруженных записей. Календарь использует отдельный API и получает все доступные подтверждённые/активные выезды независимо от поиска и первых 100 заявок. .ics остаётся копией без синхронизации переносов.

## Обновление через Cloud Shell

```bash
cd "$HOME/liikkuva"
git status --short
# При наличии изменений сначала сохраните их; не используйте reset --hard.
git fetch origin
git switch --track origin/feat/crm-complete-v2
python3 scripts/deploy-crm-preview.py
```

Если ветка уже существует локально: `git switch feat/crm-complete-v2 && git pull --ff-only`.

Скрипт проверяет чистоту дерева, запускает тесты и сборку, добавляет недостающие индексы (без удаления существующих) и ждёт их готовности. Затем `gcloud run deploy ... --no-traffic --tag crm-access-v2`. Основные ревизии и проценты трафика сравниваются до/после. Старый `crm-preview` сохраняется. Новые URL и ревизия выводятся скриптом. Отправка почты выключается явно.

В текущей среде нет авторизованного gcloud: Cloud Run не обновлён, URL новой ревизии не подтверждён, основной сайт не переключался. Контейнерная сборка Cloud Build и живой Preview ещё не проверены.

## Проверки

Выполнены Go-тесты всего приложения и CRM с локальным Firestore Emulator, включая конкурентное бронирование, сессии, приём заявок, P0-фильтрацию через обработчики HTTP, фото чужого заказа, запрет подмены автора, смену номера, повтор сообщения, тарифный снимок и неизменность оригинала фото. Выполнена сборка Go и проверка синтаксиса JavaScript.

Без FIRESTORE_EMULATOR_HOST интеграционные тесты пропускаются явно. Тестовые обращения в рабочей базе не изменялись. Реальным клиентам сообщения не отправлялись.

Дополнительная проверка: сводка на 105 заказах (больше страницы), ограничения исходных фото, полный цикл назначения → согласование → ремонт → возврат отчёта → принятие с сохранением всех событий.

Проверка интерфейса: `node --test tests/crm-ui.test.cjs` проверяет отсутствие клиентских кнопок у механика, наличие их у владельца и независимость финансовой сводки от загруженного списка. Эти проверки включены в скрипт обновления (нужен Node.js). Это тесты генерации интерфейса, не замена браузерной проверки опубликованного Preview.

## Заключительная сверка требований

- P0: серверные права, отсутствие draft/переписки/финансов прошлых клиентов у механика, безопасная история и тесты — реализованы.
- P1: зоны, графики, исключения, переназначение, независимый календарь, этапы, отчёт и принятие, тарифы брендов, фото с приватными оригиналами — реализованы в коде.
- При client_confirm теперь сохраняется отдельный Agreed: предложение, время, автор и ревизия согласования. Новое предложение/перенос/переназначение сбрасывают действующее согласие; предыдущий снимок остаётся в журнале событий. Старые документы без Agreed совместимы.
- Поиск по старому/новому номеру поддерживается также существующим Telegram-ботом через тот же реестр автомобилей.
- P2: единая модель сообщений, интерфейсы адаптеров, сохранение переводов, ручная почта и цепочки — реализованы. Существующий WhatsApp webhook не заменяется.
- Непроверенная внешняя часть: публикация Cloud Run, браузерный и мобильный прогон реального Preview, SMTP-доставка, провайдер входящей почты и переводчик. Для этого нужны действующие настройки/доступ к сервисам. Автоматические клиентские ответы выключены.
- HEIC/HEIF-конвертация не включена: требуется JPEG/PNG. Условная поддержка из ТЗ не заявляется как готовая.

Дополнительные тесты: отдельный снимок согласования, сброс согласия при переносе, календарь на 102 записях с ограничением по механику, сохранение перевода без изменения оригинала и запрет перевода для механика.
