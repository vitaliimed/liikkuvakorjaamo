# Liikkuva Auto Korjaamo

Рабочий исходный код сайта `https://liikkuvakorjaamo.fi` находится в `source/`.
Google Cloud project: `liikkuva-korjaamo`. Регион Cloud Run: `europe-north1`.
Firebase Hosting site: `liikkuva-liikkuva-korjaamo`.

## Обновить существующий сайт и задать пароль

В Google Cloud Shell из папки этого репозитория:

```bash
git pull --ff-only origin main
python3 update.py --set-password
```

Скрипт попросит новый пароль дважды; ввод скрыт. Минимум 12 символов.
Он определит Cloud Run сервис по опубликованной конфигурации Firebase Hosting,
проверит исходники и новую ревизию, затем переведёт на неё 100% трафика.
Работающий домен и записи DNS повторно настраивать не нужно.

Вход: `https://liikkuvakorjaamo.fi/admin`.

Почта восстановления при первой настройке: `medynikv@gmail.com`.
После входа её можно изменить в разделе **Доступ и почта**. Новый адрес
включается только после подтверждения ссылки, отправленной на этот адрес.
Пароль и выбранная почта сохраняются в Firestore при обновлениях приложения.

## Следующие обновления

```bash
git pull --ff-only origin main
python3 update.py
```

Задать другой пароль без пересборки и публикации:

```bash
python3 update.py --password-only
```

Подключить или обновить SMTP:

```bash
python3 update.py --configure-email
```

Понадобятся данные действующего почтового сервиса и подтверждённый адрес
отправителя. SMTP-ключ вводится скрыто и сохраняется через Secret Manager.
Cloudflare Email Routing обслуживает пересылку входящей почты; для отправки
писем восстановления нужен SMTP. Скрипт сам тестовые письма не рассылает.

Для включения приёма заявок после завершения настройки интеграций:

```bash
python3 update.py --enable-leads
```

Если сервис нельзя определить однозначно, скрипт остановится. Можно явно
передать `--service liikkuva-preview` или другое имя, показанное в Cloud Run.
Если привязка Hosting прочитана, указанный сервис должен совпадать с ней.

## Что находится в кабинете

- Обзор последних заявок и быстрые действия.
- Цены, контакты, изображения и оформление.
- Отдельные тексты для финской и английской версий.
- Форма заявки, услуги, примеры работ, акции и отзывы.
- SEO, индексация, аналитика и рекламные идентификаторы.
- Заявки, этапы работы, письма клиентам и модерация отзывов.
- Пароль, почта восстановления, завершение сеансов и журнал доступа.
- Поиск по настройкам и справка терминов на русском.

Текущая схема доступа — один кабинет владельца. Отдельные аккаунты сотрудников
и разграничение ролей в этом выпуске не реализованы. При работе в нескольких
окнах проверка версии настроек защищает от перезаписи чужого сохранения.

## Устройство и проверка

Сервер: Go. Хранение данных: именованная Firestore database `liikkuvakorjaamo`.
Клиентский доступ к этой базе закрыт правилами; сервер работает через IAM.
Учётные данные кабинета находятся в отдельной от контента коллекции
`<SITE_SETTINGS_COLLECTION>_private`, документ `admin_access`.

При обновлении сохраняются существующие переменные, ссылки на секреты,
коллекции и заявки. При отсутствии именованной базы скрипт создаст её в
`europe-north1`; сервисному аккаунту выдаётся `roles/datastore.user`.
Скрипт публикует закрытые клиентские правила именно для базы
`liikkuvakorjaamo`, а не для `(default)`.

Проверки:

```bash
(cd source && go test ./... && go vet ./...)
(cd source && go test -race ./...)
python3 -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/events.test.cjs tests/apps-script.test.cjs
```

Для браузерной проверки нужен Playwright и установленный Chromium:

```bash
# При уже запущенном локальном приложении:
BASE_URL=http://127.0.0.1:8080 node tests/responsive.cjs
```

Подробности выпуска и ограничения проверки: [RELEASE-20261029-RU.md](RELEASE-20261029-RU.md).
Инструкция владельца: [ADMIN-RU.md](ADMIN-RU.md).

Файлы `install.py`, `prepare.py`, `hosting.py`, `bundle/` и старые инструкции
относятся к первоначальному комплекту. Для текущего существующего сайта
используйте описанный выше `update.py`; первоначальный установщик не является
командой обновления.
