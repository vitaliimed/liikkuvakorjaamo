# Техническое задание — Liikkuvakorjaamo SEO & Landing Pages 2.0

**Сайт:** https://liikkuvakorjaamo.fi/  
**Проект Google Cloud:** `liikkuva-korjaamo`  
**Cloud Run:** `liikkuva-preview`  
**Регион:** `europe-north1`  
**Репозиторий:** `vitaliimed/liikkuvakorjaamo`  
**Технологии:** Go, HTML, CSS, JavaScript, Firestore.  
**Ветка разработки:** `feat/seo-landing-pages-v2`

## 1. Основная задача

Провести комплексную модернизацию SEO-архитектуры существующего сайта Liikkuvakorjaamo.fi.

В настоящее время некоторые внутренние страницы индексируются Google, но недостаточно проработаны с точки зрения дизайна, пользовательского опыта, SEO и конверсий.

Пример проблемной страницы:

https://liikkuvakorjaamo.fi/palvelualue

Необходимо сделать так, чтобы потенциальный клиент, попадая на любую индексируемую коммерческую страницу сайта, получал полноценную информацию об услуге и мог сразу оформить заявку на вызов механика.

Цели:

- Увеличение органического трафика.
- Повышение конверсии органического трафика в заявки.
- Улучшение позиций по целевым поисковым запросам.
- Устранение технических SEO-ошибок.
- Предотвращение SEO-каннибализации.
- Подготовка сайта к Google Ads и Meta Ads.
- Улучшение видимости сайта в поисковых системах и AI-поиске.
- Создание удобной системы управления SEO-страницами через административную панель.

Стратегическая цель — занять максимально высокие позиции по 20 основным коммерческим поисковым запросам в Helsinki, Espoo, Vantaa и Uusimaa.

## 2. Ограничения и сохранение существующего функционала

Работаем с существующим проектом. Не создаём новый сайт с нуля.

Запрещается без отдельного согласования:

- Удалять существующие индексируемые страницы.
- Изменять существующие URL.
- Массово закрывать страницы от индексации.
- Менять архитектуру CRM.
- Изменять структуру действующей базы данных CRM.
- Нарушать интеграцию с AutoHelp.fi.
- Нарушать отправку заявок в Telegram.
- Нарушать работу WhatsApp.
- Нарушать работу Brevo и электронной почты.
- Удалять существующие настройки административной панели.
- Изменять действующие цены.
- Нарушать работу Google Analytics 4.
- Отключать действующую антиспам-защиту.
- Перезаписывать секреты и переменные окружения Cloud Run.

Перед началом работ получить актуальную версию репозитория и определить текущую production-ревизию.

Не использовать старый архив сайта как единственный источник актуального кода.

## 3. Полный технический SEO-аудит

Перед внесением изменений провести аудит всех публичных страниц сайта.

Проверить:

- HTTP-статусы.
- Title.
- Meta Description.
- H1, H2, H3.
- Canonical.
- Meta Robots.
- X-Robots-Tag.
- Hreflang.
- Sitemap.xml.
- Robots.txt.
- Open Graph.
- Структурированные данные Schema.org.
- Внутреннюю перелинковку.
- Дублирующиеся страницы.
- Дублирующиеся метатеги.
- Битые ссылки.
- Цепочки редиректов.
- Soft 404.
- Страницы без внутренних ссылок.
- Мобильную адаптацию.
- Скорость загрузки.
- Наличие и работоспособность форм.
- Соответствие контента поисковым запросам.
- Индексируемость финской и английской версий.

Создать полный реестр URL с текущим состоянием и рекомендуемым действием для каждой страницы.

При наличии доступа к Google Search Console дополнительно проверить:

- Фактическую индексацию.
- Поисковые запросы.
- Показы.
- Клики.
- CTR.
- Средние позиции.
- Выбранные Google canonical URL.
- Конкуренцию нескольких страниц по одинаковым запросам.

Если доступа к Search Console нет, не делать предположений о фактической индексации и позициях. Подготовить инструкции для получения этих данных.

## 11. Технические требования SEO

### 11.1. Серверный рендеринг

Все важные элементы должны присутствовать в исходном HTML, возвращаемом сервером Go:

- Title.
- Meta Description.
- Canonical.
- H1.
- Основной текст.
- Внутренние ссылки.
- Структурированные данные.

Основной SEO-контент не должен зависеть от выполнения JavaScript.

### 11.2. Canonical

Каждая самостоятельная индексируемая страница должна иметь корректный абсолютный canonical.

Использовать HTTPS и основной домен:

https://liikkuvakorjaamo.fi/

Не допускать указания главной страницы в canonical всех внутренних страниц.

### 11.3. Sitemap.xml

Реализовать автоматическое формирование Sitemap.xml из опубликованных индексируемых страниц.

В Sitemap включать только URL:

- Возвращающие HTTP 200.
- Разрешённые к индексации.
- Имеющие корректный canonical.
- Доступные на основном домене.

Исключить:

- CRM.
- Административную панель.
- Черновики.
- Тестовые страницы.
- Страницы подтверждения заявок.
- Служебные страницы.
- URL с параметрами аналитики.
- Страницы с noindex.
- Редиректы.
- Страницы с ошибками.

Lastmod обновлять только при существенном изменении содержимого страницы.

### 11.4. Robots.txt

Проверить корректность robots.txt.

Не блокировать CSS, JavaScript и изображения, необходимые для отображения публичных страниц.

Служебные страницы должны быть защищены авторизацией, а там, где необходимо, дополнительно исключены из индексации.

Robots.txt не использовать как единственный механизм защиты данных или удаления страниц из индекса.

### 11.5. Мультиязычность

Сохранить существующие финскую и английскую версии сайта.

Для каждой локализованной страницы обеспечить:

- Корректный HTML lang.
- Индивидуальный Title.
- Индивидуальный Description.
- Индивидуальный H1.
- Собственный canonical.
- Взаимные hreflang-ссылки.
- x-default при необходимости.
- Переключение языка на соответствующую страницу.

Не указывать hreflang на несуществующие страницы.

Финский язык является приоритетным для SEO в Финляндии.

### 11.6. Структурированные данные

Реализовать корректную JSON-LD разметку, где применимо:

- Service.
- Offer.
- WebSite.
- WebPage.
- BreadcrumbList.
- FAQPage для видимого блока вопросов и ответов.

Использовать только фактические сведения о компании.

Не добавлять вымышленные рейтинги, отзывы, адреса или цены.

Не обещать расширенные сниппеты Google только на основании наличия структурированной разметки.

### 11.7. Open Graph

Для каждой публичной страницы обеспечить:

- og:title.
- og:description.
- og:image.
- og:url.
- og:type.
- og:locale.
- twitter:card.

Проверить внешний вид ссылок при отправке в WhatsApp, Telegram, Facebook и других социальных сетях.

## 12. Внутренняя перелинковка

Создать логичную систему внутренних ссылок.

Главная страница должна ссылаться на основные услуги, цены и зону обслуживания.

Страница зоны обслуживания должна ссылаться на опубликованные страницы городов и услуг.

Страницы услуг должны ссылаться на тематически связанные услуги и необходимые информационные страницы.

Страницы городов должны ссылаться на доступные в соответствующем регионе услуги.

Добавить хлебные крошки на внутренних страницах.

Все важные страницы должны быть доступны через обычные HTML-ссылки.

Не создавать чрезмерное количество однотипных ссылок с искусственно оптимизированными анкорами.
