## Тарифы: устройство и ограничения

- Источник истины: Firestore `liikkuva-korjaamo / liikkuvakorjaamo / crm_settings / tariffs`.
- AutoHelp использует `/crm/internal/autohelp-tariffs` с отдельным `CRM_AUTOHELP_TARIFF_TOKEN`. Токен не открывает клиентские заявки, финансовый журнал, тарифы Liikkuva или очередь уведомлений.
- CRM сохраняет общий справочник. AutoHelp сохраняет только свою часть; несовпадающая версия возвращает конфликт. Повтор уже принятого идентичного запроса не создаёт новую версию.
- В AutoHelp добавлена отдельная страница `/admin/tariffs`, доступная после обычного входа. Ссылка есть в админке. Дополнительные услуги создаются в CRM и затем появляются на этой странице.
- Сайт, новые заявки, подтверждения и Telegram-уведомления используют один снимок цен. Повторная отправка письма по существующей заявке использует сохранённую цену.
- Встроенные блоки выезда/диагностики обновляются автоматически. Для произвольных текстов и карточек из админки предусмотрены `{{tariff:visit}}`, `{{tariff:diagnostics}}` и `{{tariff:код_услуги}}`. Произвольный старый текст с вручную набранной ценой нельзя безопасно переписать по одному числу: такие тексты нужно один раз заменить шаблонами. Живое содержимое этих текстов из этой среды не проверено.
- При кратком сбое CRM AutoHelp может использовать последний подтверждённый снимок до 15 минут; резерв хранится в `crm_tariff_cache/autohelp` в существующей базе AutoHelp. Он не записывается обратно в CRM. При отсутствии допустимого снимка сайт/форма явно сообщает временную недоступность проверки цен, не обещая выдуманную сумму.
- У старых обращений без сохранённой цены стоимость не восстанавливается из сегодняшнего тарифа: в импортированной заявке показывается примечание о необходимости согласования. Уже импортированные и согласованные заказы не переписываются.

## Публикация на рабочие сайты

Обновления находятся в двух репозиториях:

- `vitaliimed/liikkuvakorjaamo`, ветка `feat/crm-payments-completion-20261117`.
- `vitaliimed/lending`, ветка `feat/autohelp-crm-tariffs-20261118`.

Запускать из Cloud Shell:

```bash
(
  set -euo pipefail
  cd ~/liikkuva
  if [ -n "$(git status --porcelain)" ]; then
    echo "Сначала сохраните локальные изменения."
    git status --short
    exit 1
  fi
  git fetch origin
  git switch feat/crm-payments-completion-20261117
  git pull --ff-only origin feat/crm-payments-completion-20261117
  bash scripts/publish-crm-complete.sh
)
```

Скрипт сначала получает отдельную копию AutoHelp в `~/autohelp-tariffs-20261118`, запускает его тесты и сборку. Затем обновляет существующие сервисы Liikkuva и AutoHelp, подключает тарифы, обновляет существующий worker импорта AutoHelp и подключает Telegram. Ручного этапа preview нет. Автоматические проверки Liikkuva перед переключением трафика сохранены.

Прежнюю папку AutoHelp скрипт не перезаписывает. Используется ветка GitHub, основанная на `feat/autohelp-required-registration-fi-en` (`5447d17f`). Если на рабочем AutoHelp есть изменения, которые не сохранены в этой ветке GitHub, их нужно сначала перенести: из предоставленных логов нельзя доказать отсутствие неопубликованных исходников.

Для Telegram понадобится **личный Telegram user ID владельца**. Если он уже настроен, скрипт использует его. Иначе запросит число в Cloud Shell. Это не номер телефона и не ID группы. Владелец и механики должны открыть существующего бота и нажать Start. Токены скрипт читает из текущей конфигурации; вставлять их в чат не требуется.

Если у бота уже есть другой webhook, скрипт остановит именно подключение бота, сохранив остальные выполненные этапы. Нельзя молча заменить неизвестный работающий обработчик.

После устранения причины можно повторить только нужный этап, без пересборки сайтов:

```bash
cd ~/liikkuva
python3 scripts/connect-autohelp-tariffs.py --apply
bash scripts/install-autohelp-crm-sync.sh
python3 scripts/connect-crm-telegram.py --apply
```

## Firestore и индексы

Дополнительные поля и коллекции финансов/отчётов перечислены в `CRM-PAYMENTS-20261117-RU.md`. Этот этап добавляет:

## Откат

Снимки конфигураций перед публикацией: `~/.liikkuva-releases/complete-*/`. Подключение тарифов и Telegram сохраняет дополнительные приватные снимки с правами `0600`.

При откате переключайте трафик на сохранённую ревизию и, если домен использует Firebase Hosting tag, возвращайте этот тег. Не удаляйте Firestore и не восстанавливайте всю базу из старой копии.

Старая версия финансов может удалить неизвестные новые поля при перезаписи: после отката старого кода приостановите финансовые изменения до совместимого исправления. Для отключения только тарифной интеграции AutoHelp удаляется `CRM_AUTOHELP_TARIFF_URL`; при этом вернётся прежнее поведение сайта, а сохранённые снимки заявок останутся. Перед таким отключением проверьте прежние цены сайта.

Webhook нельзя откатывать отдельно от его секрета и обработчика. Резервная копия `getWebhookInfo` не содержит секрет, поэтому секрет берётся из сохранённой конфигурации ревизии/Secret Manager.
